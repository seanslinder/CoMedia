# Спецификации Вариантов Использования (Use Case Specifications)

## ВИ-1: Аутентификация пользователя в системе
* **Актор:** Пользователь (Гость)
* **Описание:** Процесс ввода имени пользователя для получения доступа к созданию комнат или входу в приватные комнаты.
* **Предусловия:** Пользователь открыл главную страницу приложения.
* **Основной сценарий:**
  1. Пользователь вводит желаемое имя (Username) в форму входа.
  2. Пользователь нажимает кнопку «Войти».
  3. Система проверяет наличие пользователя с таким именем в базе данных.
  4. Если пользователя нет, система создает новую запись.
  5. Система генерирует JWT-токен, сохраняет его на стороне клиента (например, в LocalStorage) и авторизует пользователя.
  6. Система перенаправляет пользователя в главное меню (список комнат).
* **Альтернативные сценарии:**
  * *3а. Имя пользователя не соответствует валидации:* Система выдает сообщение об ошибке. Возврат к шагу 1.

## ВИ-2: Создание комнаты совместного просмотра
* **Актор:** Авторизованный пользователь
* **Описание:** Создание новой виртуальной комнаты для просмотра медиа с настройками приватности.
* **Предусловия:** Пользователь прошел аутентификацию (ВИ-1).
* **Основной сценарий:**
  1. Пользователь инициирует действие создания комнаты.
  2. Система отображает форму настройки комнаты (Название, Тип: приватная/публичная).
  3. Пользователь вводит название и выбирает тип «Публичная».
  4. Пользователь подтверждает создание.
  5. Система генерирует уникальный ID комнаты, сохраняет в БД и назначает пользователя владельцем.
  6. Система перенаправляет пользователя в интерфейс созданной комнаты.
* **Альтернативные сценарии:**
  * *3а. Выбор приватной комнаты:* Система запрашивает ввод пароля.
  * *4а. Ошибка базы данных:* Система уведомляет о невозможности создать комнату.

## ВИ-3: Подключение к виртуальной комнате
* **Актор:** Пользователь (Авторизованный или Гость)
* **Описание:** Вход в существующую комнату по прямой ссылке или выбором из списка.
* **Предусловия:** Комната существует в базе данных.
* **Основной сценарий:**
  1. Пользователь выбирает публичную комнату или переходит по ссылке.
  2. Система проверяет статус комнаты.
  3. Устанавливается WebSocket-соединение между клиентом и сервером.
  4. Система отправляет клиенту текущее состояние комнаты.
  5. Пользователь добавляется в список активных зрителей.
* **Альтернативные сценарии:**
  * *2а. Комната приватная:* Система запрашивает пароль. (Гость должен авторизоваться).
  * *2б. Комната не существует:* Система отображает ошибку и перенаправляет на главную страницу.

## ВИ-4: Синхронизированное воспроизведение медиа
* **Актор:** Владелец комнаты (или пользователь с правами управления)
* **Описание:** Управление плеером (Play, Pause, Seek), которое синхронно отражается у всех участников.
* **Предусловия:** Пользователь находится в комнате, медиа загружено в плеер.
* **Основной сценарий (на примере паузы):**
  1. Актор нажимает кнопку «Пауза» в видеоплеере.
  2. Клиент немедленно ставит локальное видео на паузу и отправляет Socket-событие `player_pause` на сервер.
  3. Сервер принимает событие, проверяет права актора.
  4. Сервер транслирует событие `sync_pause` всем остальным подключенным клиентам.
  5. Клиенты ставят видео на паузу и корректируют время.
* **Альтернативные сценарии:**
  * *3а. Недостаточно прав:* Локальный клиент сбрасывает управление, сервер игнорирует запрос.

## ВИ-5: Добавление пользовательского медиафайла
* **Актор:** Авторизованный пользователь
* **Описание:** Загрузка видеофайла формата MP4 на сервер для добавления его в плейлист.
* **Предусловия:** Пользователь авторизован и находится в комнате.
* **Основной сценарий:**
  1. Пользователь выбирает опцию «Загрузить видео».
  2. Выбирает файл (MP4) на устройстве.
  3. Система производит клиентскую валидацию.
  4. Файл отправляется на сервер через HTTP POST запрос с JWT-токеном.
  5. Сервер сохраняет файл, создает запись в БД и возвращает URL.
  6. Видео добавляется в очередь комнаты, участники получают оповещение.
* **Альтернативные сценарии:**
  * *3а. Файл не прошел валидацию:* Ошибка. Отправка отменяется.

## ВИ-6: Общение в текстовом чате
* **Актор:** Пользователь
* **Описание:** Отправка и получение текстовых сообщений внутри комнаты в режиме реального времени.
* **Предусловия:** Пользователь подключен к комнате.
* **Основной сценарий:**
  1. Пользователь вводит текст сообщения.
  2. Нажимает «Отправить».
  3. Приложение через WebSocket отправляет сообщение на сервер.
  4. Сервер сохраняет сообщение в базу данных.
  5. Сервер рассылает сообщение всем активным клиентам.
  6. Интерфейсы обновляются, отображая новое сообщение.
